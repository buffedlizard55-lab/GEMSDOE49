Executive summary — how to make a submission

What this competition asks for, what the scorer actually measures, and the exact steps to file a valid entry. Written so that someone who has never seen the repo can act on it.

The 60-second version

  1. Download the GeoTIFF at the top of the overview page.
  2. Go to drivendata.org → competition 306 → Submit (you must be logged in and have joined the competition).
  3. Upload the file, give it the unique name gems49-gate_ortho_w0.25-40k-20261006T213721Z, and paste the short comment from below.
  4. Press submit. The form validates the file; a score appears on the leaderboard within minutes.

That is the whole procedure. The rest of this page is the contract your file must satisfy, the three ways files get rejected, and how the score is computed.

Three failures that actually happen

1. “Predicted values must be in range [0, 1]” — because of NaN inside the footprint

A file that leaves interpolation holes inside the mapped area has no NaN-safe problem at the edges but fails as soon as the form takes a plain min/max over the array. If your pipeline produces any interior NaN, fill it (0 is the safe fill: it adds no false-positive mass) before writing. This repository's writer refuses to emit such a file at all, and the test suite constructs the failure on purpose (tests/test_gate.py::test_mode_a_nan_inside_footprint_is_rejected).

2. “Predicted values must be in range [0, 1]” — because of an out-of-range finite value

Standardising a field to z-scores, or leaving a nodata sentinel of −3.4e38 in the array, produces finite values outside [0,1]. Clip after normalising, and never write a sentinel. The -zeros variant is provided precisely because some readers turn NaN outside the footprint into a large negative number.

3. A rejected or duplicated name

Each submission needs its own name and a short comment (the form asks for both). Do not reuse a previous submission's name: the scorer stores one file per name and a relabelled prior file is explicitly out of bounds here. scripts/uniqueness_check.py compares a candidate against every prior raster this repository could obtain and refuses a relabel.

What the score is

The competition uses a distance-weighted Tversky index, not accuracy. With 100 m pixels and a 300 m triangular kernel k(d) = max(1 - d/300, 0), and the organizer's weights α = 0.2 for false positives and β = 0.8 for false negatives:

DTI = TP_w / (TP_w + 0.2·FP_w + 0.8·FN_w)
  • Credit is graded by distance: a pixel 150 m from a scored fault earns half its value.
  • Missing a fault costs four times as much as an equivalent false positive.
  • Pixels already in the public USGS/INGENIOUS fault catalogue are masked out of scoring entirely — redrawing the known map earns nothing.

The organizer's own worked example (TP_w = 3.00, FP_w = 1.89, FN_w = 2.00 → 0.60) is reproduced to 0.602652 by tests/test_metric.py. Exact marginal algebra: adding one pixel at kernel credit k raises the denominator by exactly 0.2, so it pays iff k > 0.2·s where s is the current score — at s = 0.28 that is 0.056, i.e. every pixel within 283 m of a scored fault pixel pays. Binary, sparse submissions beat smooth probability maps under this metric; the shaping lever is area, not calibration.

Rules and limits worth knowing before you spend a slot

  • Three scored submissions per rolling week OFFICIAL.
  • The public leaderboard is a spatial chunk of the region; the private score comes from other chunks, and the final round is re-scored against an expanded expert label set after every team's best submission is reviewed. Rank on the public board is a weak predictor of the private result — spread submissions across genuinely different hypotheses rather than micro-tuning one.
  • Predictions are interpreted as a per-pixel confidence that a new fault exists there; "new" includes newly mapped geometry of an existing fault system.
  • Submission slots are the scarce resource. This repository's rule: a candidate is only eligible after it beats the single-layer baseline on held-out segments and passes the relabel check.
